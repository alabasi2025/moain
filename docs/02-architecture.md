# البنية التقنية — منصة إضاءات

## 1. الصورة العامة

```
 الطالب (جوال/آيباد)   المعلمة (لابتوب)    الإدارة (جوال)
          │                   │                  │
          └──────── HTTPS ────┴──────────────────┘
                              │
             ┌────────────────▼─────────────────┐
             │  Cloudflare Pages + Functions     │  ← مجاني تقريباً
             │  Hono (TypeScript, SSR)           │
             │  ─ المصادقة والصلاحيات            │
             │  ─ الحصص والتوزيع                 │
             │  ─ الواجبات والرسائل والمالية     │
             └──────┬──────────────┬────────────┘
                    │              │
             ┌──────▼─────┐  ┌─────▼────────────────┐
             │ D1 (SQLite)│  │ R2 (ملفات+تسجيلات)   │
             │ كل البيانات│  │ رفع مجزّأ + بث Range  │
             └────────────┘  └──────────────────────┘

   الحصص المباشرة:
   ┌─────────────────────────┐     ┌──────────────────────────────┐
   │ قاعات الزوم الأربع       │     │ سيرفر البث الخاص (VPS ~25 ر) │
   │ (حسابات العميل الحالية)  │     │ Jitsi Meet (Docker) + JWT     │
   │ رابط ثابت لكل قاعة       │     │ meet.<domain>                 │
   └─────────────────────────┘     └──────────────────────────────┘
```

## 2. لماذا هذا التصميم؟

| القرار | السبب |
|---|---|
| Cloudflare للمنصة | بدون سيرفر يُدار، مجاني للحجم الحالي، وسريع في الخليج |
| R2 للتسجيلات | **بدون رسوم تحميل (egress)**، فمشاهدة الطلاب للتسجيلات لا تكلف شيئاً |
| زوم أولاً ثم Jitsi | يستغل الاشتراك المدفوع الموجود، ويلغي الزوم المجاني |
| Jitsi مستضاف ذاتياً | سعر ثابت مهما زادت الحصص، بدل الدفع بالدقيقة، ومفتوح المصدر بلا ارتباط بمزود |
| التسجيل من متصفح المعلمة | Jibri (مسجّل Jitsi) يحتاج ~4GB رام لكل تسجيل متزامن، والتسجيل من المتصفح تكلفته صفر ويتوسع مع أي عدد |
| SSR بدون إطار | صفحات خفيفة جداً على الجوالات، و SEO ممتاز |

## 3. قاعدة البيانات

مخطط كامل في `migrations/0001_init.sql`. الاصطلاحات:
- **المال بالهللة** (`INTEGER`): 100 هللة = 1 ريال، فلا أخطاء كسور.
- **النسب بنقاط الأساس**: 10000 = 100%.
- **الأوقات** ثواني يونكس UTC، و**التواريخ المالية** `YYYY-MM-DD` بتوقيت الرياض.

```
users ──< enrollments >── courses ──< lessons ──< recordings ──< recording_parts
  │           │   │          │  │                     └──< recording_views
  │           │   │          │  └──< assignments ──< submissions
  │           │   └── partners (الجهة التي جلبت الطالب)
  │           ├──< installments  (الأقساط المتوقعة)
  │           └──< payments      (التحويلات الفعلية)
  ├──< sessions                 courses ──< expenses
  └──< messages                 courses ──< payouts (صرف للمعلمة/الجهة)
zoom_rooms ──< lessons     leads (طلبات الموقع)     settings     login_attempts
```

### حساب الأقساط (بدون تخزين حالة)
حالة كل قسط **تُحسب** ولا تُخزن: تُجمع التحويلات لكل تسجيل وتوزَّع على الأقساط من الأقدم استحقاقاً (FIFO)، ثم تُحدد الحالة (`paid` / `partial` / `overdue` / `due_soon` / `upcoming`). كذا لا تحصل حالة غير متطابقة أبداً، وحذف أو تعديل تحويل يعيد الحساب فوراً. (`domain.ts → allocateInstallments`)

### ربح وخسارة الدورة
```
المحصّل          = Σ التحويلات لكل طلاب الدورة (حتى المنسحبين)
مستحق المعلمة     = نسبة × المحصّل | مبلغ × عدد الطلاب النشطين | مبلغ ثابت
مستحق الجهات      = Σ (المحصّل من طالب × نسبة الجهة التي جلبته)
صافي الربح        = المحصّل − مستحق المعلمة − مستحق الجهات − مصروفات الدورة
الرصيد المتبقي    = المستحق − المصروف فعلياً (payouts)
```
تُحسب كل الدورات بـ **4 استعلامات مجمعة فقط** (بدون N+1). (`finance.ts → courseFinances`)

## 4. تدفق الحصة

```
جدولة حصة ──► allocate():
                ├─ provider=jitsi ⇐ بث المنصة
                └─ ابحث عن أول قاعة زوم نشطة بدون حصة متداخلة [start, end)
                     ├─ وُجدت ⇐ zoom + zoom_room_id
                     └─ لم توجد ⇐ (تلقائي) jitsi  |  (زوم فقط) رفض
             INSERT ... WHERE NOT EXISTS(تعارض)   ← حماية من السباق بين طلبين متزامنين

دخول الحصة (GET /lessons/:id):
   canAccessCourse(user) ✔  ثم  canJoinNow (من −15 دقيقة حتى +30 بعد النهاية) ✔
   ├─ zoom  ⇐ الرابط + الرمز (ومفتاح المضيف للمعلمة فقط)
   └─ jitsi ⇐ JWT موقّع {room, moderator, exp} ⇐ IFrame API داخل الصفحة
إنهاء الحصة ⇐ ends_at = الآن، فتتحرر القاعة فوراً لحصة أخرى
```

## 5. تدفق التسجيل

```
المتصفح (المعلمة)                       Worker                       R2
getDisplayMedia(التبويب+الصوت) + المايك
  │ خلط الصوت (AudioContext)
  │ MediaRecorder كل 4 ثوانٍ
  │ تجميع حتى 8MB بالضبط (شرط R2: الأجزاء متساوية ما عدا الأخير)
  ├── POST /api/lessons/:id/recordings ──► createMultipartUpload ─────► ✔
  ├── PUT  /api/recordings/:id/parts/N ──► uploadPart (إعادة محاولة ×6) ► ✔
  │   ... أثناء الحصة ...
  ├── (عند الإيقاف) إصلاح مدة WebM في الجزء 1 بنفس الطول ⇐ إعادة رفع الجزء 1
  └── POST /api/recordings/:id/complete ─► تحقق التسلسل والأحجام ⇐ complete
                                          ready_at = الآن، expires_at = +48 ساعة
```

**إصلاح مدة WebM:** ملفات MediaRecorder بدون مدة، فيظهر المشغل بلا شريط تقديم صحيح. `webm-duration.js` يضيف عنصر Duration في رأس الملف **مع الحفاظ على نفس الطول تماماً** (يحذف MuxingApp/WritingApp ويملأ الفرق بعنصر Void)، فيبقى شرط R2 متحققاً. مُختبَر بـ ffprobe.

**المشاهدة:** `/media/recordings/:id` ⇐ جلسة ✔، تسجيل في الدورة ✔، لم تنتهِ الصلاحية ✔، `Sec-Fetch-Dest` = video ✔، ثم بث من R2 مع دعم `Range` (206).

**الحذف بعد 48 ساعة، بثلاث طبقات:**
1. كل طلب مشاهدة يتحقق من `expires_at`، فالتسجيل المنتهي لا يُعرض أبداً حتى قبل حذفه.
2. تنظيف انتهازي (`maybeCleanup`) مرة كل ساعة كحد أقصى عند أي طلب: يحذف من R2، ويلغي الرفوعات المعلقة، ويحذف الجلسات المنتهية.
3. (اختياري) Worker مجدول (`deploy/cleanup-cron-worker.js`) + قاعدة Lifecycle في R2 كشبكة أمان أخيرة.

## 6. الأمان

| التهديد | الحماية |
|---|---|
| سرقة كلمات المرور | PBKDF2-SHA256 بـ 100,000 تكرار وملح لكل مستخدم، ومقارنة بزمن ثابت |
| سرقة الجلسة | توكن عشوائي 256-bit في كوكي `HttpOnly; Secure; SameSite=Lax`، وقاعدة البيانات تحفظ SHA-256 للتوكن فقط |
| التخمين | حد 8 محاولات خاطئة لكل رقم و40 لكل IP كل 15 دقيقة (الـ IP أعلى لأن طلاب شبكة واحدة يشتركون فيه) |
| CSRF | رفض أي طلب معدِّل إذا لم يكن `Origin`/`Sec-Fetch-Site` من نفس الموقع |
| الوصول لموارد الغير (IDOR) | فحص على الخادم لكل مورد: `canAccessCourse` / `canManageCourse` / `canMessage` / مالك الرفع |
| XSS | JSX يهرّب كل المخرجات تلقائياً |
| حقن SQL | كل الاستعلامات بمعاملات مربوطة (`bind`) |
| رفع ملفات خبيثة | قائمة امتدادات مسموحة، وحد 25MB، وتنزيل بـ `attachment` و`nosniff` |
| حقن صيغ Excel | تهريب الخلايا التي تبدأ بـ `= + - @` في CSV |
| تسريب التسجيلات | بدون رابط مباشر، و48 ساعة، وعلامة مائية باسم ورقم الطالب، وسجل مشاهدات |
| دخول غرف البث بدون إذن | JWT موقّع لكل غرفة ولمدة محددة، والضيوف معطلون، و`ENABLE_AUTO_OWNER=0` |
| ترويسات | `X-Frame-Options: SAMEORIGIN`، `X-Content-Type-Options`، `Referrer-Policy`، `HSTS` |
| إعادة التوجيه المفتوح | `next` يقبل مسارات داخلية فقط |

> **مصارحة:** منع تصوير الشاشة بالجوال مستحيل تقنياً في أي منصة. العلامة المائية المتحركة باسم الطالب ورقمه هي الرادع الفعلي، لأن أي تسريب يُعرف مصدره.

## 7. الأداء
- حجم الـ Worker حوالي 56KB مضغوط، والصفحات HTML جاهزة من الخادم بدون أطر ثقيلة.
- الاستعلامات مفهرسة (`idx_lessons_time`, `idx_lessons_room`, `idx_inst_due`, …)، والمالية مجمعة.
- الملفات الثابتة مخزنة عبر Service Worker، أما الصفحات والتسجيلات فلا تُخزن أبداً (خصوصية).

## 8. حدود معروفة وتطوير لاحق
| البند | الحالي | التطوير المقترح |
|---|---|---|
| الدفع | تسجيل التحويلات يدوياً | بوابة ميسر/Tap + تسوية تلقائية |
| الزوم | رابط ثابت لكل قاعة (PMI) | Zoom API: اجتماع لكل حصة + استيراد التسجيل السحابي تلقائياً |
| التسجيل على iPad/الجوال | غير مدعوم من المتصفحات | المعلمات على لابتوب (حسب وضعهم الحالي) |
| الإشعارات | داخل المنصة | Web Push / SMS / واتساب للأعمال |
| التحويل لـ MP4 | WebM (يعمل على Safari 17+ وكل المتصفحات الحديثة) | تحويل على السيرفر عند الحاجة |
